## Behavioral Improvements / Fixes

### ApplicationSet webhook responses now match the API server webhook

The ApplicationSet controller's webhook endpoint now handles requests the same way as the API
server's `/api/webhook` endpoint:

- Payloads larger than the `webhook.maxPayloadSizeMB` value in the `argocd-cm` ConfigMap (default
  50MB) are rejected with `400 Bad Request`. Previously, the ApplicationSet webhook had no payload
  size limit.
- A GHCR event that fails signature verification is rejected with `401 Unauthorized` instead of
  `400 Bad Request`.
- When a payload cannot be parsed, the response body is a generic `Webhook processing failed`
  message. The parser error is logged by the ApplicationSet controller instead of being returned to
  the caller.

If you monitor the ApplicationSet webhook's response codes or bodies, update any checks that relied
on the previous behavior.

## Other Changes

### Revoked token resync interval

`argocd-server` now reloads revoked tokens from Redis every 5 minutes instead of every 15 seconds. The interval is configurable with `ARGOCD_SESSION_REVOKED_TOKEN_RESYNC_DURATION`. See [Revoked token resync](../user-management/index.md#revoked-token-resync).

### Cluster cache settings in `argocd-cmd-params-cm`

Eight application controller cluster cache settings that were only available as environment variables can now also be
set with `argocd-application-controller` flags and `argocd-cmd-params-cm` keys. The environment variables keep working
with the same names and defaults. See [argocd-cmd-params-cm.yaml](../argocd-cmd-params-cm-yaml.md) for the new
`controller.cluster.cache.*` keys.

A list semaphore of `0` used to block every cluster sync, and an events processing interval of `0` with batch events
processing enabled used to crash the controller. Set through `argocd-cmd-params-cm` or an environment variable, these
values now log a warning and use the default instead. Passed as an explicit `argocd-application-controller` flag, they
stop the controller at startup with an error.

The Argo CD Helm chart sets each `argocd-cmd-params-cm` key on the controller explicitly. Until the chart adds the new
keys, Helm users can set these settings as environment variables with `controller.env` in the chart values.

> [!WARNING]
> The controller manifests now set these eight environment variables with `valueFrom`. If you add any of them to the
> controller with a Kustomize strategic merge patch that sets `value`, the merged container has both `value` and
> `valueFrom`, and Kubernetes rejects it. Move the setting to `argocd-cmd-params-cm` before you upgrade.
