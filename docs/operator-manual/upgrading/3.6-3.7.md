## Behavioral Improvements / Fixes

### ApplicationSet webhook responses now match the API server webhook

The ApplicationSet controller's webhook endpoint now handles requests the same way as the API
server's `/api/webhook` endpoint:

- Payloads larger than the `webhook.maxPayloadSizeMB` value in the `argocd-cm` ConfigMap (default
  50MB) are rejected with `400 Bad Request`. Previously, the ApplicationSet webhook had no payload
  size limit.
- A GHCR event that fails signature verification is rejected with `401 Unauthorized` instead of
  `400 Bad Request`.
- When a payload cannot be parsed, the response body is a generic `Webhook processing failed`
  message. The parser error is logged by the ApplicationSet controller instead of being returned to
  the caller.

If you monitor the ApplicationSet webhook's response codes or bodies, update any checks that relied
on the previous behavior.

## Other Changes

### Revoked token resync interval

`argocd-server` now reloads revoked tokens from the cache every 5 minutes instead of every 15 seconds. The interval is configurable with `ARGOCD_SESSION_REVOKED_TOKEN_RESYNC_DURATION`. See [Revoked token resync](../user-management/index.md#revoked-token-resync).

### Redis replaced with Valkey

Argo CD now uses Valkey instead of Redis for its cache layer due to licensing changes in Redis v8 (AGPL/SSPL). Valkey is an open-source Redis fork using the BSD 3-Clause license.

#### What changed

- **Single-node deployments**: Redis → Valkey 8.0.11-alpine
- **HA deployments**: Redis → Valkey 8.0.11-alpine (StatefulSet with Sentinel + HAProxy)
- **Image registry**: Changed from `public.ecr.aws/docker/library/redis` to `docker.io/valkey/valkey`

#### Impact on upgrades

**No action required for most users.** Valkey is 100% protocol-compatible with Redis. The upgrade process:

1. Deployment `argocd-redis` (or StatefulSet `argocd-redis-ha-server` for HA) updates with new Valkey image
2. Pods restart with Valkey containers
3. Cache rebuilds automatically (Argo CD uses cache with persistence disabled)
4. Components reconnect and resume normal operation

**Downtime**: Minimal for single-node (~30 seconds cache rebuild), none for HA (rolling update maintains quorum).

#### External Redis users

If you run Argo CD with an external Redis instance (not the bundled deployment), **no changes are required**. Argo CD's Redis client libraries work with both Redis and Valkey. You may continue using Redis or migrate to Valkey at your convenience.

#### Resource names unchanged

Kubernetes resource names remain `argocd-redis`, `argocd-redis-ha-server`, etc. for backward compatibility. Only the container images changed.

#### Licensing

Valkey uses the BSD 3-Clause license, avoiding the AGPL/SSPL licensing concerns introduced in Redis v8.
