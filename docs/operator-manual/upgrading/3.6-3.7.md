## Behavioral Improvements / Fixes

### New `argocd-cluster-ca-cm` ConfigMap for cluster CA certificates

The `ca.crt` key of this ConfigMap can hold one or more PEM encoded CA certificates, which Argo CD
trusts in addition to the system trust store when it verifies the Kubernetes API server of any
cluster whose secret does not set `tlsClientConfig.caData`. If all your clusters use certificates
from the same internal CA, you can now configure that CA once instead of copying it into every
cluster secret.

The installation manifests now include this ConfigMap without any data, so nothing changes until you
set `ca.crt`. Clusters that define their own `caData`, and clusters with
`tlsClientConfig.insecure: true`, never use the bundle. See the
[declarative setup documentation](../declarative-setup.md#default-ca-bundle-for-cluster-connections)
for more details.

- No action is required when upgrading.
- If you install Argo CD with your own manifests, or with a Helm chart that does not create this
  ConfigMap, create `argocd-cluster-ca-cm` yourself with the `app.kubernetes.io/part-of: argocd`
  label before using the feature.
- Anyone who can edit `argocd-cluster-ca-cm` controls which CAs Argo CD trusts for clusters without
  their own `caData`. Limit write access to it in the same way as for cluster secrets.
