# v3.6 to 3.7

## Breaking Changes

### Kustomize patches that set cluster cache environment variables

If you set any of the following environment variables on the application controller with a
Kustomize strategic merge patch that uses `value`, Kubernetes rejects the updated controller
StatefulSet or Deployment, and the controller stays on the previous version. The controller
manifests now read these variables from `argocd-cmd-params-cm`, so your patch gives the same
variable a second source.

Before you upgrade, move each setting to its `argocd-cmd-params-cm` key and remove it from the
patch:

| Environment variable | `argocd-cmd-params-cm` key |
|---|---|
| `ARGOCD_CLUSTER_CACHE_RESYNC_DURATION` | `controller.cluster.cache.resync.duration` |
| `ARGOCD_CLUSTER_CACHE_WATCH_RESYNC_DURATION` | `controller.cluster.cache.watch.resync.duration` |
| `ARGOCD_CLUSTER_SYNC_RETRY_TIMEOUT_DURATION` | `controller.cluster.cache.sync.retry.timeout` |
| `ARGOCD_CLUSTER_CACHE_LIST_PAGE_SIZE` | `controller.cluster.cache.list.page.size` |
| `ARGOCD_CLUSTER_CACHE_LIST_PAGE_BUFFER_SIZE` | `controller.cluster.cache.list.page.buffer.size` |
| `ARGOCD_CLUSTER_CACHE_LIST_SEMAPHORE` | `controller.cluster.cache.list.semaphore` |
| `ARGOCD_CLUSTER_CACHE_ATTEMPT_LIMIT` | `controller.cluster.cache.attempt.limit` |
| `ARGOCD_CLUSTER_CACHE_RETRY_USE_BACKOFF` | `controller.cluster.cache.retry.use.backoff` |

## Behavioral Improvements / Fixes

### ApplicationSet webhook responses now match the API server webhook

The ApplicationSet controller's webhook endpoint now handles requests the same way as the API
server's `/api/webhook` endpoint:

- Payloads larger than the `webhook.maxPayloadSizeMB` value in the `argocd-cm` ConfigMap (default
  50MB) are rejected with `400 Bad Request`. Previously, the ApplicationSet webhook had no payload
  size limit.
- A GHCR event that fails signature verification is rejected with `401 Unauthorized` instead of
  `400 Bad Request`.
- When a payload cannot be parsed, the response body is a generic `Webhook processing failed`
  message. The parser error is logged by the ApplicationSet controller instead of being returned to
  the caller.

If you monitor the ApplicationSet webhook's response codes or bodies, update any checks that relied
on the previous behavior.

## Other Changes

### Revoked token resync interval

`argocd-server` now reloads revoked tokens from Redis every 5 minutes instead of every 15 seconds. The interval is configurable with `ARGOCD_SESSION_REVOKED_TOKEN_RESYNC_DURATION`. See [Revoked token resync](../user-management/index.md#revoked-token-resync).

### Cluster cache settings in `argocd-cmd-params-cm`

You can now configure the application controller's cluster cache with `argocd-cmd-params-cm` keys
or controller flags. The environment variables you use today keep working, unless you set them
with a Kustomize patch (see Breaking Changes). See
[argocd-cmd-params-cm.yaml](../argocd-cmd-params-cm-yaml.md) for the `controller.cluster.cache.*`
keys and their defaults.

If you install Argo CD with the Helm chart, keep setting these values with `controller.env` until
the chart supports the new keys.
