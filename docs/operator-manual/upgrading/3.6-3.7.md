### Repository CA keeps system trust by default

When a Helm, OCI Helm, or Kustomize-based application uses a repository configured with a
custom CA via the Certificates UI / `argocd-tls-certs-cm` ConfigMap, Argo CD previously passed
`--ca-file` to the Helm binary (or relied on a single CA file for Git). Helm then used that
file as the sole TLS trust store, which breaks chart downloads that redirect to public HTTPS
endpoints (for example Nexus pre-signed S3 URLs).

Starting with Argo CD 3.7, when a repository CA is configured Argo CD:

- exposes that CA through `SSL_CERT_DIR` for Helm and Kustomize invocations (keeping normal
  system trust), and
- for native Helm / OCI HTTP clients, starts from the Go system certificate pool and appends
  the repository CA.

This keeps chart downloads working for private registries that redirect to publicly trusted
endpoints without maintaining a manually merged CA bundle.

**Impact:**

- Operators who relied on the repository CA alone to restrict Helm TLS trust to their private
  CAs will now also trust the system public roots for Helm / OCI operations that use a
  repository-specific CA.
- Operators who manually merged public roots into their repository CA bundle can remove the
  redundant public CAs from that bundle; Argo CD keeps system trust automatically.

**Mitigation:** Set `reposerver.merge.repository.ca.with.system: "false"` in the
`argocd-cmd-params-cm` ConfigMap (or set `ARGOCD_MERGE_REPOSITORY_CA_WITH_SYSTEM=false`
or `--merge-repository-ca-with-system=false` on `argocd-repo-server`) to disable this
feature and pass only the repository CA. See
[Repository CA and system trust](../../user-guide/private-repositories.md#repository-ca-and-system-trust).
