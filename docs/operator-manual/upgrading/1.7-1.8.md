# v1.7 to 1.8

## The argocd-application-controller converted to StatefulSet

The `argocd-application-controller` has been converted to StatefulSet. That means you need to manually delete `argocd-application-controller` Deployment after upgrading.
Similarly if you decided to rollback to v1.7 don't forget to delete `argocd-application-controller` StatefulSet.


## Health assessment of argoproj.io/Application CRD has been removed

The health assessment of `argoproj.io/Application` CRD has been removed (see [#3781](https://github.com/argoproj/argo-cd/issues/3781) for more information).
You might need to restore it if you are using app-of-apps pattern and orchestrating synchronization using sync waves. Add the following resource customization in
`argocd-cm` ConfigMap:

```yaml
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-cm
  namespace: argocd
  labels:
    app.kubernetes.io/name: argocd-cm
    app.kubernetes.io/part-of: argocd
data:
  resource.customizations: |
    argoproj.io/Application:
      health.lua: |
        hs = {}
        hs.status = "Progressing"
        hs.message = ""
        if obj.status == nil or obj.status.sync == nil or obj.status.sync.comparedTo == nil then
            hs.message = "waiting for the application status"
            return hs
        end

        local function observed(spec, compared_to)
            if type(spec) ~= "table" or type(compared_to) ~= "table" then
                return spec == compared_to
            end
            for k, v in pairs(spec) do
                if not observed(v, compared_to[k]) then return false end
            end
            for k in pairs(compared_to) do
                if spec[k] == nil then return false end
            end
            return true
        end

        local compared_to = obj.status.sync.comparedTo
        if obj.spec.source ~= nil then
            if not observed(obj.spec.source, compared_to.source) then
                hs.message = "waiting for the controller to observe the current source"
                return hs
            end
            if not observed(obj.spec.destination, compared_to.destination) then
                hs.message = "waiting for the controller to observe the current destination"
                return hs
            end
        end

        if obj.status.health ~= nil then
            hs.status = obj.status.health.status
            if obj.status.health.message ~= nil then
                hs.message = obj.status.health.message
            end
        end
        return hs
```
> To modify an existing installation with no existing `resources.customizations`, you can save the `data:` stanza to file and patch the configmap with e.g.: `kubectl -n argocd patch configmaps argocd-cm --patch-file argocd-cm-patch.yaml`

The `comparedTo` checks return `Progressing` while the recorded status belongs to an older spec. `status.sync.comparedTo` records the source and destination a sync verdict was computed against, and the controller compares the same fields to decide whether a comparison is stale. Without the check, the parent's sync wave gate can progress prematurely after a child Application update ([#4669](https://github.com/argoproj/argo-cd/issues/4669), [#5585](https://github.com/argoproj/argo-cd/issues/5585)). The example guards the source and destination of single-source Applications. Applications without `spec.source` (multiple sources, or a source hydrator) are not gated; compare `spec.sources` with `status.sync.comparedTo.sources`, or the hydrator's effective source, the same way to cover them.

## gRPC metrics are disabled by default

The gRPC metrics are not exposed by default by `argocd-server` and `argocd-repo-server` anymore. These metrics appear
to be too expensive so we've decided to disable them by default. Metrics can be enabled using
`ARGOCD_ENABLE_GRPC_TIME_HISTOGRAM=true` environment variable.  

From here on you can follow the [regular upgrade process](./overview.md).
